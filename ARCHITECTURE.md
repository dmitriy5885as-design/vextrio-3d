# Архитектура FORMA

Зависимости направлены от приложений к пакетам. `shared` не зависит от других пакетов. `document`, `commands`, `geometry`, `snapping`, `tools` используют общие типы. `editor` использует `document` и `commands`. `viewport` использует `editor` и `geometry`. `file-io` использует `document`. `ui` содержит токены и словарь. Проверка `pnpm check:deps` анализирует импорты пакетов и запрещает циклы.

Документ — JSON-совместимые данные с `schemaVersion: 1`. Three.js — проекция документа: Map сопоставляет ID объекта с Mesh. При изменениях существующие Mesh обновляются на месте, удалённые освобождают геометрию и материал. Геометрия пересоздаётся только при изменении её описания. Изменения камеры и состояния UI не пересоздают сцену. Render запускается по запросу, ResizeObserver обновляет размер камеры и renderer. Damping отключён, непрерывного RAF-цикла нет. При потере WebGL-контекста показано сообщение; после восстановления запрашивается перерисовка.

`useEditor` разделяет поля документа (`project`) и временные поля UI (`selected`, `tool`, `grid`, тема, чувствительность). Подписка viewport сравнивает только значимые ссылки и параметры; изменения камеры не вызывают синхронизацию объектов. Для будущих больших сцен следует разделить Zustand на физические stores и заменить широкие React-подписки селекторами.

Изменения документа проходят через `mutate` и `SnapshotCommand`. История содержит не более 100 пар снимков; простая и надёжная схема для Foundation. Перетаскивание манипулятора меняет только Mesh; при отпускании записывается одна команда. Числовые поля фиксируются по Enter/потере фокуса. Слайдер материала сейчас создаёт запись на каждое изменение; объединение слайдеров — следующая оптимизация. Камера является навигационным состоянием, не историей редактирования.

Файловые операции сначала проверяют/сериализуют данные. Ошибка открытия не заменяет текущий проект. Браузер скачивает Blob без изменения исходного файла. Нативный адаптер вызывает Rust-команды, выбранный путь хранится в Mutex; запись через tempfile в той же папке, sync_all, persist. Неуспешная запись не помечает проект сохранённым. Нативный слой требует проверки на Windows.

Будущий Worker получает сериализуемое описание геометрии и ID запроса, возвращает transferable Float32Array/Uint32Array. Реализация Three.js остаётся на главном потоке; OpenCascade должен жить в Worker. Модель документа не зависит от классов Three.js, хотя текущий контракт отображаемой геометрии их использует — этот тип нужно заменить типизированными массивами до интеграции Worker.

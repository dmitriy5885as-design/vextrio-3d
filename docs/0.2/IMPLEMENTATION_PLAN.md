# План реализации 0.2 Sketch

Статус: архитектура утверждена. S1.1/S1.2 реализованы для ревью — [результаты и границы проверки](S1_REPORT.md). Rust/Windows gate остаётся открытым. S2.1/S2.2 реализованы как независимое ядро и harness — [отчёт S2](S2_REPORT.md). S3 и последующие этапы не начаты. Зависимости перечислены явно; «независимый этап» здесь означает ограниченную область изменений и отдельную приёмку, а не отсутствие зависимости от геометрического основания.

## Правила прохождения этапов

- Перед S1 требуется утверждение решений из [README](README.md). Само добавление документации не является утверждением.
- Один этап разбивать на маленькие проверяемые коммиты по указанным срезам. Не смешивать UI, смену формата и подключение OpenCascade в один большой rewrite.
- Unit/build/dependency gates зелёные после каждого среза; существующие E2E — после интеграционного изменения. Новый сценарий из SPECIFICATION обязателен для каждой пользовательской функции.
- Не делать следующую интеграцию поверх сломанной базовой функции. При регрессии исправить или откатить только свой срез, не удалять работающие подсистемы.
- Внутренний алгоритм может приниматься через headless harness, но пользовательская функция не объявляется готовой до связанного E2E. Столбец «сценарий» связывает их заранее.
- Откат формата не пишет поверх источника; старый reader/legacy bridge сохраняются до прохождения миграционных fixtures.

## Первый разрешаемый этап: S1

Входит только исправление границы команд, regression/compatibility fixtures и доказуемые границы пакетов. Никаких новых панелей, платных редакций, wasm, смены формата по умолчанию или новых sketch-кнопок.

Порядок: сначала постоянные воспроизведения с ожидаемым безопасным результатом → исправление → типы/build → unit → существующие E2E → отчёт. Валидатор не должен превратить корректные операции 0.1 в отказы. Для Undo/Redo проверить обе ветви history и сохранение камеры. Локальные пользовательские файлы и исходные fixtures не перезаписываются.

Выход S1: список изменённых функций, проверенные сценарии и результаты; отдельный перечень остающихся P1. Если потребуется менять геометрическую область, формат либо семантику миграции, сначала обновить решение и вынести изменение на согласование.

## Критический путь и отложенная работа

Критический путь: command safety → topology/числа → segment intersections → planar faces → document/render bridge → drawing → direct editing → contexts → worker/files/offline regression. Срезы fixtures, протокола и файловых adapters могут разрабатываться независимо только после фиксации общего контракта; это не разрешение смешивать незавершённые API.

OpenCascade.js, Push/Pull и boolean не являются способом пропустить S2/S3. После Sketch выделяется следующий RFC Solid: extrude с топологией боковых граней/отверстий, collision/intersection policy, solid validation, provenance и проверяемый сценарий построения стены/проёма. Только затем объёмные функции помогают достичь сценария целого дома. Следующие релизы остаются бесплатными.

# VEXTRIO 3D — результаты S3 Sketch

Дата: 25 октября 2026. Основание: S2 и ребрендинг, PR #4 / commit `264967dd15ddd060af1a8e63f09a5be7149d429b`. PR #1–4 не объединяются автоматически. Работа разделена на S3.1 и S3.2; пользовательские инструменты рисования остаются S6.

## S3.1 — пересечения и атомарные рёбра

`intersections.ts` вычисляет пересечения конечных 3D-отрезков через векторные произведения и параметры обоих отрезков. T/X, endpoint contact, коллинеарное совпадение и частичный overlap дают параметры разбиения. Для почти параллельного случая одного угла недостаточно: проверяются расстояния обоих концов до обеих поддерживающих прямых. Proper crossing не превращается в overlap только из-за малого угла. Построенные точки повторно проверяются по мировому расстоянию.

`edge-builder.ts` работает только с candidate-копией модели: детерминированно переиспользует существующие вершины, отказывает в неоднозначном/транзитивном кластере, сортирует параметры, строит минимальные уникальные интервалы и заменяет все coedge uses разделённого ребра. Неизменённые рёбра сохраняют ID; split получает новые IDs и parameterRange. Повторное рисование существующего ребра, включая обратное направление, не создаёт истории. Дубли из существующей S2-модели тоже канонизируются. После сварки повторно проверяются уже построенные рёбра: неразрешённое пересечение вызывает NUMERICAL_AMBIGUITY, а не частичную публикацию.

Для S3.1 алгоритм возвращает промежуточный кандидат: Body membership и финальное принятие относятся к S3.2/coordinator. Этот промежуточный объект напрямую в документ не публикуется.

## S3.2 — плоские области и заполнение

`arrangement.ts` выбирает поддерживающие плоскости существующих граней/явного эскиза и кандидаты по неколлинеарным точкам рёбер. Все релевантные концы проверяются на принадлежность плоскости. Для неплоского пространственного контура единой плоской области не получается — остаются рёбра. Пересечение только проекций, skew и разнесённые параллельные плоскости не свариваются. Реальное пересечение в 3D внутри одного geometry context обрабатывается как общая вершина, согласно утверждённой архитектуре.

На каждой плоскости строится производный граф: Tarjan удаляет bridges из обходов областей, исходящие полурёбра сортируются по полуплоскости и точному BigInt orientation из S2; atan2-сортировки нет. Next выбирается относительно обратного использования ребра. Обходятся только bounded положительные области; внешний неограниченный контур и dangling branches не создают граней. Это не перебор всех простых циклов.

Вложенность определяется point location. Внутренние обходы становятся holes внешнего cell, одновременно внутренний cell имеет собственную грань, если он заполнен. Для concave regions sample выбирается scanline-поиском по полосам между вершинами, с проверкой попадания вне отверстий; centroid не используется как гарантированно внутренняя точка.

`sketch.ts` сравнивает before/after arrangement и заполненность before faces. Новый bounded cell вне прежних bounded regions заполняется автоматически; дочерние области существующей грани наследуют заполненность. Ранее пустая bounded область сохраняет пустоту. Поддержаны face-only delete и явный make-face по полному внешнему контуру cell — необходимые операции для проверяемой семантики отверстий. Удаление рёбер/контекстов пока не добавлено.

Неизменённые Face/Loop/Coedge IDs и ориентация сохраняются, в том числе для противоположно ориентированных компланарных граней. Разделённые грани получают новые IDs и lineage; front/back material IDs наследуются с учётом ориентации, без нового material subsystem. Bodies пересчитываются по инцидентности через вершины, рёбра и грани; отверстие не создаёт ложную disconnected body. Слияние/разделение тел отражается в lineage. Существующие shell uses перенаправляются на replacement faces; результат дополнительно проверяет общий S2 validator.

## Интеграция и надёжность

- Сохранены GeometryModel/GeometryPolicy/GeometryDelta/GeometrySession. LocalGeometryBackend исполняет insert-segments, make-face и face-only delete через PreparedGeometryChange. Move-vertices сохраняет прежний путь S2; он ещё не является инструментом произвольной перестройки arrangement после перемещения.
- Delta содержит before/after, inverse проверяется до публикации. Reject/no-op/preview не изменяют модель, revision и redo. Cancel, Undo, смена session и конкурирующий commit по-прежнему отвергают устаревшие ответы. Undo/Redo использует записанные IDs и данные.
- В validator уточнено одно правило: прямолинейная промежуточная вершина контура после split допустима, обратный ход/вырождение не допускаются. Иначе T-junction на границе делал бы корректную грань невалидной.
- Vertex merge может ссылаться на выжившую существующую вершину в lineage. Для прочих сущностей сохраняется правило новых descendants. Loop/coedge ссылки направляются на соответствующие replacement faces/uses.
- Исправлена обнаруженная коллизия S2: независимые GeometrySession больше не выделяют одинаковые IDs вида request/0/operation. Namespace содержит geometry prefix и уникальный номер сессии авторитетного процесса; история восстанавливает сохранённые IDs. Сериализованная provenance/резервирование IDs после перезапуска и document-wide coordinator остаются интеграцией S4; Worker не должен самостоятельно создавать запросы от имени документа.
- Three.js/React/DOM/OCCT не участвуют в вычислениях. UI v1, primitive viewport bridge, .v3d reader/writer, app identity, ребрендинг и логика S1 не изменены. Нет новых кнопок, Push/Pull, boolean, форматов экспорта или обещаний готового 0.2.

## Реальные входы и выходы

[Полный воспроизводимый корпус S3_EXAMPLES.json](S3_EXAMPLES.json) содержит входные координаты, все таблицы GeometryModel с IDs и lineage, а не только ожидаемые счётчики. Он строится исполнением production-функций prepareSketch и validatePrepared:

```powershell
node scripts/sketch-examples.mjs
pnpm exec vitest run tests/sketch-corpus.test.ts
```

Единицы — метры; плоскость примеров — z=0.

| Операция           | Реальные входные точки/отрезки                                   | Вершины | Рёбра | Coedges / loops | Грани и площади          |
| ------------------ | ---------------------------------------------------------------- | ------: | ----: | --------------- | ------------------------ |
| Прямоугольник      | (0,0,0)→(4,0,0)→(4,3,0)→(0,3,0)→(0,0,0)                          |       4 |     4 | 4 / 1           | 1: 12 м²                 |
| Диагональ          | К предыдущему добавить (0,0,0)→(4,3,0)                           |       4 |     5 | 6 / 2           | 2: 6 + 6 м²              |
| X                  | (-2,0,0)→(2,0,0), (0,-2,0)→(0,2,0)                               |       5 |     4 | 0 / 0           | 0; общая вершина (0,0,0) |
| Внутренний квадрат | В прямоугольник добавить (1,1,0)→(2,1,0)→(2,2,0)→(1,2,0)→(1,1,0) |       8 |     8 | 12 / 3          | 2: 1 + 11 м²             |

Например исходная грань имеет ID `example/rectangle/face/8`; после диагонали она retired, а две новые грани перечислены в lineage с reason=split. Undo возвращает исходный ID; Redo не запускает allocator повторно. Вложенный квадрат не накладывается поверх площади 12 м²: внешний cell имеет настоящий inner loop и площадь 11 м². Удаление внутренней грани оставляет отверстие; unrelated insertion его не заполняет.

## Проверки

- `pnpm test`: **176/176**, 14 suites. Прежние 128 и 48 новых S3: 12 пересечений/split, 35 операции/интеграция, 1 полный golden corpus.
- `pnpm test:e2e`: **9/9** текущих браузерных сценариев v1/ребрендинга. Это регрессия действующего UI, а не вымышленный E2E инструментов рисования S6.
- `pnpm build`: strict TypeScript + Vite успешно. `pnpm check:deps`: 12 workspaces, нет циклов/незаявленных imports. Dependencies и lockfile не менялись.
- Дополнительный corpus: oblique 3D crossing, nearly-parallel, X/T/multiway, overlaps/reverse/order, concave L, dangling branch, несколько отверстий/bridge, nested rings, skew/stacked planes/warped loop, мировые допуски при nonuniform scale, перенос к 1e8, исходные duplicate edges/near vertices, opposite face normals, все coedge uses на перпендикулярных плоскостях, ошибки/preview/cancel/stale/redo, disjoint IDs контекстов.

Группы и компоненты: операция привязана к одной GeometryModel/definition и не получает геометрию соседнего контекста. Совпадение мировых координат не сваривает разные определения. Несколько placements одного component definition по утверждённой архитектуре намеренно разделяют одно определение: это не независимые копии. Resolver occurrence path и преобразование ввода каждого экземпляра — S4/S5; в S3 проверены изоляция моделей, ID и истории.

## Численные и ресурсные границы

Intersection constructions и plane projection остаются Float64; orientation-предикат даёт точный знак для спроецированных double, но не превращает построение точки в exact arithmetic. Используется GeometryPolicy по мировому extent, не экранный epsilon. Canonical points проверяются относительно исходных отрезков и результат повторно проверяется на неразрешённые пересечения.

Референсная реализация перебирает пары: до 256 новых / 512 исходных отрезков на операцию, 2048 canonical vertices, 64 поддерживающих плоскостей, до 250000 пар итоговых рёбер; далее действуют лимиты S2 (512 uses/loop, 20000 сущностей, JSON/validation budgets). При превышении RESOURCE_LIMIT, документ и история не меняются. Это не benchmark производительности больших моделей. Пространственные индексы, fast predicates и локальная перестройка без полного перебора — последующие оптимизации с сохранением corpus.

Точечное касание/самокасание отверстий, неразличимые под допуском области, не-простые bounded walks и невосстановимые numerical ambiguities отвергаются атомарно. Shell не проверяется на объём/самопересечение и не объявляется solid. Произвольные пересечения поверхностей, edge deletion/merge-face policy, пересечения после move-vertices и полноценная редактируемая иерархия UI не входят в этот этап. Local backend синхронно вычисляет ограниченный candidate; cancel проверяется на границе async ответа, прерывание внутри CPU-цикла требует Worker S9.

## Windows и следующие задачи

Rust/Cargo в текущем окружении недоступен; native Windows build/NSIS upgrade/offline запуск не подтверждены. Web build и E2E не заменяют Windows gate.

Далее: S4 — production v2 dispatcher/миграция v1 без потери размещений, полный DocumentDelta и render/picking bridge. S5 — размеры, привязки, occurrence transform. S6 — инструменты рисования с реальным preview и пользовательские Sketch E2E. Затем Worker/performance rollout S9 и отдельный будущий Solid RFC. Прежние PR остаются черновиками до отдельного решения о принятии.

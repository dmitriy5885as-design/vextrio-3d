# S2 — независимая топология и транзакции

Дата: 24 октября 2026. Основание — утверждённая архитектура, S1 PR #2 (`f61b88a6f8561d858b9a8e954275ee99134a314d`). Это инженерный этап S2.1/S2.2; FORMA 0.2 Sketch ещё не готова.

## Что реализовано

- `packages/geometry` стал независимым TypeScript-ядром без runtime-зависимостей. Branded IDs, таблицы Vertex/Edge/Coedge/Loop/Face/Shell/Body, GeometryPolicy, плоскости и размещения. ID не является индексом массива отображения. Allocator детерминирован, учитывает зарезервированные, в том числе удалённые ID; replay использует сохранённые delta.
- Validator проверяет уникальность ключей/ID, внешние материалы и контекст, концы рёбер, длины, замкнутые ориентированные обходы, ownership coedges/loops, плоскостность, самопересечение одного контура, winding, расположение/пересечения отверстий, членство и связность Body/Shell. Связность тела учитывает инцидентность через грань: отверстие не создаёт ошибочное отдельное тело.
- Классификация wire/sheet/closed-shell/non-manifold учитывает кратность использования рёбер и связность веера граней у вершины. `closed-shell` — только топологическая классификация, не сертификат solid/объёма.
- GeometryCatalog проверяет определения групп/компонентов, соответствие parent/child, уникальное владение геометрией, единственное размещение group, общие component placements, достижимость и отсутствие циклов. Это внутренний контракт, не новый файловый формат и не миграция v1.
- Float64 координаты, правые ортонормальные PlaneFrame, quaternion placement, положительные масштабы с ограничением обусловленности. Проверка длин/плоскостей работает в мировых метрах для одного переданного placement, включая неравномерный масштаб. Без placement координаты трактуются как мировые метры при единичном размещении.
- `GeometryDelta` хранит before/after каждой изменённой сущности. Применение проверяет preconditions на копии и валидирует конечную модель. Inverse проверяется до принятия; удаление требует lineage; Undo/Redo восстанавливает исходные ID и данные без пересоздания. Это геометрическая часть будущего DocumentDelta, не замена истории v1.
- Async GeometryBackend и GeometrySession: preview вне истории, ошибки/no-op сохраняют модель/revision/redo, session/request/operation/revision/protocol/policy envelope проверяется до применения. Отмена, смена сессии, Undo и конкурирующий результат делают старую работу неприменимой. История ограничена 100 изменениями; удалённые ID остаются зарезервированы.
- Local backend реально перемещает существующие вершины и отвергает невалидный результат. Insert-segments/make-face/delete пока возвращают UNSUPPORTED_OPERATION. Кнопок, имитирующих новые инструменты, не добавлено.

## Почему перенесён PrimitiveAdapter

Единственный production-потребитель прежнего адаптера — viewport. Код генерации Three.js-примитивов перенесён без изменения поведения в `packages/viewport/src/PrimitiveAdapter.ts`, импорт viewport направлен туда. Удалены зависимости geometry → Three/shared и viewport → geometry. Старые Mesh, камеры, материалы, picking и gizmo работают прежним путём; внутренние topology-модули не включены в UI-бандл до S4. Формат проекта остаётся v1, legacy parentId не переинтерпретирован.

## Численные границы

Политика по умолчанию: distance=max(1e-7 м, 1e-12 × world bounds diagonal), angular=1e-10, maxTransformCondition=1e8; координаты ограничены ±1e9. 2D orientation использует собственный небольшой reference predicate: каждый конечный IEEE-754 double точно преобразуется в целое на решётке 2^-1074; знак детерминанта вычисляется BigInt без округления. Проверяются смена ориентации, cancellation и subnormal. Сторонний код и лицензируемая реализация не копировались.

Это точный знак для уже спроецированных double, а не доказательство точности будущего 3D-пересечения или построенной точки. BigInt-предикат не заявляется быстрым; площадь/проекция остаются Float64. Контур ограничен 512 uses; модель — 20000 сущностей, payload — 200000 JSON-узлов; пересечения границ — максимум 1000000 пар на validation. Превышение возвращает RESOURCE_LIMIT. Композиция полного occurrence path, shear и численно неоднозначные конструкции требуют следующего корпуса S3/S5.

## Ограничения и следующие задачи

S2 validator проверяет структурную целостность и отдельные грани; он ещё НЕ является полной arrangement/intersection-проверкой модели. Перекрытия отдельных компланарных граней, канонизация совпадающих вершин/рёбер, полнота разбиения и пересечения разных поверхностей относятся к S3. Это нельзя обходить вызовом validator после произвольного рисования. Shell не проверен на самопересечение и объём.

Настоящий Worker, render DTO/transfer buffers, OCCT/WASM и его payload не реализованы. Backend — заменяемый async port; Worker S9 должен проходить тот же corpus. PreparedGeometryChange работает с одной существующей GeometryModel; создание/удаление контекстов, материалы/ссылки и полный DocumentDelta — интеграция S4. Lock в harness — переданное разрешение; production-авторизация документа остаётся в S1 editor и должна оборачивать геометрическую команду в S4.

Windows/Cargo gate остаётся открытым: установленного Rust toolchain нет, native build и offline Windows запуск не подтверждены. S2 не меняет Rust-код и не устраняет этот критерий выпуска.

Далее S3.1: устойчивые 3D/coplanar пересечения отрезков, T/X/overlap, endpoint canonicalization, split всех uses и lineage. Затем S3.2 arrangement/автообразование граней, S4 миграция и отображение v2, S5 точный ввод/привязки, S6 реальные инструменты рисования. Обязательны сценарии и регрессии; работающие подсистемы не переписываются.

# Техническое задание VEXTRIO 3D 0.2 Sketch

Статус: для утверждения. Реализация только после согласования архитектуры. Приоритеты и бесплатность обязательны по [PRODUCT_STRATEGY](../../PRODUCT_STRATEGY.md). Сущности и алгоритмы определены в [ARCHITECTURE](ARCHITECTURE.md), контракты — в [CONTRACTS](CONTRACTS.md).

## 1. Границы релиза

Пользователь строит размерный плоский план/профиль в пространстве: линии, прямоугольники и замкнутые ломаные образуют редактируемые рёбра и настоящие грани; пересечения разбивают геометрию; можно выбирать вершины/рёбра/грани, исправлять размеры, создавать группы и экземпляры компонентов, сохранять и продолжать работу. Одновременно продолжают работать примитивы и проекты 0.1.

Нет подписки, обязательной регистрации, облачного вычислителя и платных лимитов. Не устанавливать удалённые fonts/scripts/WASM как runtime-зависимость Windows.

0.2 не включает Push/Pull, boolean тел, криволинейные B-Rep поверхности, полноценный решатель постоянных параметрических constraints, BIM и импорт .skp. Реальные объёмные операции следуют отдельным этапом Solid. Круг/дуга отложены до контракта кривых: не заменять их незаявленной ломаной под видом точной окружности. Производственные ограничения явно перечисляются в справке, неподдерживаемые кнопки отключаются.

Внутреннюю топологию component редактировать только после явного входа в definition.

## 3. FSM инструмента и предпросмотр

Состояния линии: idle → startPoint → resolvingEnd → pendingCommit → следующий startPoint; cancel/error возвращают в контролируемое состояние. Rectangle: idle → firstCorner → resolvingOppositeCorner → pendingCommit → idle. Отдельные состояния numericEntry и temporaryNavigation не изменяют document.

ToolPort принимает события pointer/key/dimension/context и возвращает overlay/intent. Pointer capture фиксируется на gesture, снимается по pointerup, pointercancel, Escape, blur, смене проекта/инструмента, потере WebGL. Активный инструмент владеет ЛКМ; OrbitControls получает её только в navigation mode. Правый клик не должен одновременно завершать геометрию и вращать камеру. Cursor и статус объясняют доступное следующее действие.

Предпросмотр включает создаваемые и разделяемые рёбра, заливку кандидатов граней, source marker, размер и привязку. Недопустимый результат окрашен отдельно и сопровождается текстом; цвет не единственный сигнал. Непринятый preview не попадает в дерево, файл, историю или другие экземпляры компонента как постоянная геометрия. Hover обновляется локально, тяжёлая topology preview — с отменой устаревших запросов. Финальный commit вычисляет результат тем же backend/GeometryPolicy, а не принимает растеризованную картинку.

Escape отменяет незавершённый сегмент и завершает цепочку, уже принятые сегменты остаются. Enter подтверждает валидный числовой ввод, а не дублирует последний щелчок. Уход из окна отменяет gesture preview, не откатывает принятые команды. Worker error оставляет последний валидный документ и снимает busy state.

## 4. Привязки и числовой ввод

Candidate solver ищет endpoint, истинное intersection, midpoint, on-edge, on-face, ось, grid. Стартовое окно поиска — 8 CSS px независимо от devicePixelRatio; выход из текущей привязки — 12 px (hysteresis). Геометрическая близость проверяется отдельно. Отбор учитывает active context, видимость, рабочую плоскость, revision, occlusion policy и выбранные фильтры.

Порядок разрешения: явно заданные числовые/осевые constraints → endpoint/intersection → midpoint → on-edge → on-face → axis inference → grid. Внутри класса — screen distance, затем стабильный ID для детерминизма. Несовместимая точка отбрасывается; точный размер не должен silently подменяться ближайшим snap. Если выполняется несколько constraints, решается их пересечение; если решения нет, commit запрещён с объяснением. Shift удерживает текущее направление inference; X/Y/Z задают ось активной системы, повторное нажатие снимает lock. Привязка к чужой группе создаёт совпадающую координату в текущем контексте, не общую VertexId.

Ввод длины: десятичные числа с точкой или запятой, суффиксы `mm/мм`, `cm/см`, `m/м`; без суффикса — units проекта. Для прямоугольника ширина и высота разделяются `;`, например `4000 мм;3000 мм`. Пробелы вокруг числа/единицы разрешены; смешанные десятичные разделители, NaN/Infinity, пустая строка, выражения JavaScript и переполнение отвергаются. Обычная длина > tolerance; отрицательные координаты допустимы в полях позиции, отрицательная длина не меняет направление без явного управления.

Показывать и использовать одно parsed значение. Числовой ввод не округляется к сетке. Значение `2,5 м` в проекте с миллиметрами создаёт 2500 мм, хранится как 2,5 метра. Изменение units не масштабирует сцену. Округление подписи не изменяет координаты. Сохранённые «размеры» 0.2 — справочные измерения или непосредственные команды; постоянный параметрический constraint solver не заявляется.

## 6. Undo/Redo и транзакции

Последовательность line commit, split/face creation, edit, material, group/component, delete, conversion и изменения properties обратима. Compound операция даёт один history item. Принятие кандидата и изменение history атомарны; ошибка не очищает redo. Новый успешный edit после Undo очищает redo. Непрерывный drag/slider фиксируется один раз; Escape откатывает только preview.

Транзакции содержат before/after entities, lineage и remap selection. Geometry result с устаревшей revision, sessionId либо активным context отвергается. Undo возвращает content token сохранённого состояния и снимает dirty при совпадении токенов; revisions остаются монотонными. При загрузке нового проекта история начинается заново. SnapshotCommand остаётся для legacy до перевода операций; нельзя держать две конфликтующие истории в разных подсистемах.

## 7. Формат, миграция и совместимость

Новая запись — `.v3d`, `format:'forma'`, `schemaVersion:2`, geometry policy version, entities/definitions/materials/camera/provenance/references. Входной dispatcher различает v1/v2; неизвестная обязательная версия/representation отвергается до изменения проекта. Необязательные namespaced extensions roundtrip-сохраняются и не исполняются. Render buffers, selection, caches, OS paths, WASM pointers и Undo history не являются обязательными данными файла.

Миграция v1→v2 выполняется над копией: каждый объект становится legacy primitive node с тем же ID, descriptor, видимостью/блокировкой, именем, мировым transform как отображала 0.1. Material values, units и camera сохраняются. parentId не превращается автоматически в transform-родителя: он сохраняется как legacyParentId metadata с предупреждением о старой неинтерпретируемой иерархии. Нельзя ни двигать детей, ни притворяться, что v1 уже содержала рабочие группы.

Сферы/цилиндры сохраняют точные исходные primitive descriptors, не обрабатываются как сотни независимых граней автоматически. Куб/плоскость также остаются legacy до явной конверсии. Конверсия создаёт topology с provenance и поддержкой Undo, bake local transform в active definition, проверяет последствия совпадений. Faceted sphere/cylinder хранит выбранную сегментацию и метку approximation; исходный descriptor сохраняется в provenance для отчёта, не как второй редактируемый источник истины.

Миграция детерминирована, не меняет оригинальный файл, после открытия предлагает сохранить копию v2. Первый Save мигрированного документа направляется в новый файл, не затирает v1 автоматически. Открытие v2 приложением 0.1 не поддерживается: обратную совместимость reader не путать с возможностью старой версии читать новую геометрию. Дополнительный v1 export возможен только для полностью представимых legacy-only документов и не входит в обязательный релиз; никакой молчаливой потери sketch-сущностей.

Проверяются ссылки, циклы definition graph, ownership, замкнутость loops, coedges, принадлежность bodies, planarity, intersections boundaries, materials, arrays, численная область. Открытие большой/вредоносной сцены имеет управляемый ресурсный бюджет и отказ без изменения прежнего проекта. Общие byte-size ограничения одинаковы Web/Desktop и документированы как технические.

FileService различает cancel, write-confirmed и download-started. После ошибки open/save или отмены не меняются документ, dirty и прежний путь. Изменение имени в Save As применяется только после принятой операции либо остаётся отдельным явно редактируемым действием с понятной отменой. OpenNative имеет candidate/accept/reject; не сбрасывает старый путь до validation. Native сохраняет через tempfile в той же папке, flush/sync и замену, с испытанием отказа доступа и прерывания. Браузерный fallback честно сообщает скачивание без гарантии записи на диск.

## 8. Тестирование и выпуск

Unit/integration: GEO-01…16, валидаторы всех сущностей, duplicate IDs, orphan refs, definition cycles, locks ancestors, world/local transforms, парсер единиц, приоритеты snap и hysteresis, точный Undo/Redo, worker crash/cancel/stale/session mismatch и malformed DTO. Проверять topology invariants и площади, не совпадение внутренних треугольных индексов. Добавить property-based/metamorphic проверки с фиксированными seeds: reorder вставок, translation/rotation, reverse edge direction, roundtrip и undo возвращают геометрически эквивалентный результат. Разные порядки операций не обязаны генерировать одинаковые новые IDs.

Golden fixtures v1: все четыре примитива, units, материалы, hidden/locked, parent chains, perspective/ortho, большой/микро масштаб, невалидный файл. Golden v2: contour, split, отверстие, shared components, retired references. Fixtures содержат seed/ожидаемую версию и не перезаписываются автоматически без рассмотрения изменения.

Обязательные E2E:

1. Новый → линия 4 м → перпендикуляр 3 м → замыкание → грань 12 м² → диагональ → две по 6 → Undo/Redo → Save → reopen → те же связи/размеры.
2. Прямоугольник → внутренний контур → удалить внутреннюю грань → сторонняя линия → отверстие сохраняется → Save/reopen.
3. Группа профиля → два component instances → edit shared → make unique → независимая правка → Save/reopen.
4. v1 fixture → открыть → сравнить placements/materials/camera → сохранить копию v2 → reopen → исходный v1 hash не изменился.
5. Рисование → numeric `2,5 м` при units mm → temporary orbit → продолжить → Escape → ни лишнего ребра, ни history item.
6. Невалидный файл/заблокированная геометрия/ошибка worker/отмена save → прежний проект доступен, не теряет содержимое.
7. Установленный Desktop при отключённой сети → запустить, построить профиль, сохранить, закрыть/открыть → восстановить профиль. Никаких сетевых запросов, от которых зависит работа.

E2E использует пользовательские действия и сохранённый документ для проверки topology; не считает количество треугольников доказательством граней. Picking UI отдельно проверяется по EntityId, не по случайному screen coordinate из большой сцены. При доступе к тестовым diagnostics их включать только в test build.

Стартовые **цели для измерения**, не достигнутые характеристики: на зафиксированном референсном ПК hover/overlay p95 ≤16 ms, ответ snap p95 ≤50 ms для 10k рёбер, локальный commit p95 ≤250 ms для 1k затронутых рёбер; render updates без полного rebuild незатронутых assets.

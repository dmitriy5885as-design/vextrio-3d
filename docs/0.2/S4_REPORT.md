# S4 — production документ и подключение топологии

Дата: 25 октября 2026. Статус: реализация подготовлена к приёмке; S5 не начат. Основание — PR 5, S3. [Аудит пяти PR и блокеров](S4_AUDIT.md).

## Результат

Рабочий редактор открывает .v3d с настоящей S3-топологией, отображает её грани с отверстиями, рёбра и вершины, выбирает канонические ID, сохраняет и повторно открывает документ без изменения геометрии. Это проверено через обычный файловый интерфейс браузера, а не отдельный geometry harness.

## Production Document v2

Источник истины находится в packages/document/src/v2.ts. Корень содержит format: "forma", schemaVersion: 2, name, units, camera, rootDefinitionId, definitions, nodes, geometries, materials, geometryPolicy, references, provenance и extensions. Геометрия содержит исходные таблицы S2/S3: vertices, edges, coedges, loops, faces, shells, bodies. Треугольники визуализации в файл не записываются.

Definition владеет геометрией и упорядоченным списком childNodeIds. Group/component nodes ссылаются на определения; экземпляры общего компонента используют одну геометрию и разные occurrencePath. Владение, типы сущностей, ссылки, циклы, уникальность ID, материалы, политика точности и все мировые вхождения проверяются до принятия документа. Ошибка не меняет документ, dirty-state или Undo/Redo.

Persisted EntityRef содержит definitionId, geometryId, kind, entityId, occurrencePath. Таблица references сохраняет внешние ссылки; provenance сохраняет geometry-scoped retired IDs, operationId, descendants и диапазоны параметров. Validator проверяет отсутствие циклов lineage, разрешимость потомков и невозможность переиспользовать retired ID. Ссылка на удалённую сущность может храниться как tombstone; picking выбирает только живые сущности.

Полные affine матрицы вычисляются из цепочки quaternion TRS. Вложенные повороты и неравномерный масштаб не сворачиваются ошибочно обратно в один TRS. GeometryPolicy контролирует обусловленность всей композиции; мировой допуск применяется к операциям через occurrence context.

## Совместимость и миграция

v1 остаётся поддерживаемой веткой Document. Открытие не меняет формат автоматически. Пункт «Файл → Преобразовать в v2» выполняет детерминированную обратимую миграцию одной командой. Новые проекты создаются в v2.

Старый объект становится legacy-primitive node: исходные ID, описание примитива, локальный Euler Transform, visible/locked и материал сохраняются. Euler — намеренная compatibility ветка; native group/component используют quaternion TRS. Старый parentId сохраняется как legacyParentId и не начинает внезапно преобразовывать детей. Старая иерархия 0.1 была метаданными, поэтому все мигрированные примитивы находятся в корневом определении с прежними абсолютными координатами.

Неизвестные пользовательские поля объекта сохраняются в node.extensions, материала — в material.userData, корня — в extensions.legacyFields. Неизвестные поля канонических записей сохраняются при последующих legacy правках. Коллизии создаваемых root/material IDs разрешаются детерминированно; Unicode ID старых объектов не переименовываются. Материалы копируются при независимой правке legacy объекта. Золотые v1 fixtures не изменены.

Старым инструментам предоставляется вычисляемое legacy представление. В v2 нет второго сохраняемого массива objects, способного разойтись с каноническими nodes/materials. Валидация и правила блокировки защищают запись из этого представления.

## Команды и история

GeometrySession.prepare использует существующий backend и проверку PreparedGeometryChange, но не принимает изменение в собственную историю. После проверки актуальности revision редактор передаёт forward/inverse delta в GeometryDocumentCommand общей CommandHistory. Валидация полного candidate, включая triangulation, выполняется до записи истории. Камера сохраняется как текущая и не делает подготовленный ответ устаревшим; изменение документа, replace и Undo/Redo делают.

Проверены смешанные native/legacy команды, Undo/Redo с теми же ID, невалидная операция, pending ответ после замены/другой команды, отмена, изменение камеры во время подготовки. Параллельные операции используют уникальные session IDs; operation IDs не конфликтуют после открытия сохранённого файла. Изменение общей геометрии запрещено при заблокированном вхождении; видимость и блокировка native nodes также проходят общую историю.

## Render/picking bridge

TopologyBridge строит производные Three.js buffers из канонической модели. Грани триангулируются Earcut 3.0.2 с индексами отверстий; проверяются индексы, ненулевые площади, центры треугольников внутри области, ориентация и суммарная площадь. Earcut имеет ISC лицензию, копия включена в public/licenses/earcut.txt и попадает в dist. Three.js не вычисляет документную топологию.

Передняя и задняя стороны имеют отдельные материалы. Рёбра представлены LineSegments, вершины Points; каждый результат picking разрешается в исходный EntityRef. Не создаются канонические рёбра по диагоналям триангуляции. GPU coordinates вычисляются относительно геометрического origin, исходные координаты остаются числами JSON/Float64; проверен перенос на 100 миллионов метров.

Выбор учитывает видимость предков, перекрытие поверхностью, близость вершины/ребра и render revision. Отверстие не имеет невидимого picking Mesh. Два экземпляра возвращают один entityId, но разные occurrencePath. Новый bridge сначала строится полностью, затем заменяет старый; ресурсы освобождаются при ошибке и замене. Изменение только камеры не перестраивает buffers.

UI сохраняет бренд, примитивы, свойства, gizmo, темы и навигацию. Native свойства показывают ID и геометрию; удаление грани действительно меняет топологию через общую историю. Native группы/компоненты представлены деревом с рабочими действиями видимости/блокировки. Рисование и манипуляторы native вершин здесь не заявляются.

## Реальные входные данные

Воспроизводимые файлы: tests/fixtures/v2/hole.v3d и components.v3d. Генератор: node scripts/document-examples.mjs. Он использует production S3 prepareSketch, а затем production serializeProject/validation.

Внешний контур: (0,0,0) → (4,0,0) → (4,3,0) → (0,3,0) → (0,0,0). Внутренний: (1,1,0) → (2,1,0) → (2,2,0) → (1,2,0) → (1,1,0). После S3 face-only удаления внутренней области получены 8 вершин, 8 рёбер, 2 loop и одна грань с отверстием. Площадь 12−1=11 м², визуализация — 8 треугольников. Обходы, отверстие, материалы, ID и provenance сохранены в .v3d.

Второй файл использует ту же геометрию общего component definition. Первое вхождение имеет путь [instance/group, instance/one] и перенос −5 по X; второе [instance/two] и +5 по X. Браузер выбирает грань в точках (−2,1.5,0) и (8,1.5,0), подтверждая одинаковый ID и разные пути.

## Проверяемые пользовательские сценарии

1. Открыть hole.v3d через «Открыть». Щёлкнуть внутри внешней области: свойства показывают грань 11 м²; по правому ребру — edge ID; по углу — vertex ID. Щелчок в отверстии не выбирает грань.
2. Сохранить, повторно открыть скачанный файл. Сравнить полные geometry tables и ID; выбрать те же грань/ребро.
3. Удалить грань через свойства, добавить куб, дважды Undo; восстановлены сначала отсутствие куба, затем исходная топология. Redo воспроизводит изменения.
4. Открыть components.v3d: выбрать оба вхождения. Скрыть родительскую группу — её геометрия не выбирается; Undo возвращает её. Заблокировать второй экземпляр — удаление общей грани через первый запрещено; Undo снимает ограничение.
5. Открыть golden v1, проверить положение детей, материал и трансформации. Преобразовать в v2; Undo возвращает исходный v1. Старые инструменты продолжают работать после преобразования.
6. Попытаться открыть повреждённый v2 или выполнить невалидное изменение. Действующий проект, dirty-state и ветви истории сохраняются.

Браузерный screenshot test-results/v2-topology.png просмотрен: реальное отверстие видно, канонический edge ID показан в свойствах, интерфейс VEXTRIO сохранён. Это локальный артефакт прогона, не подмена E2E статичной картинкой.

Нативная Windows-сборка вызвана, но остановилась до компиляции: cargo metadata — program not found. NSIS, WebView2, нативные диалоги, atomic save и offline работа установленного приложения не проверены. Это обязательный открытый критерий выпуска, несмотря на успешные браузерные проверки на Windows.

S4 использует существующий ограниченный local async backend, не настоящий Web Worker. Сохраняются отмена и защита от stale; вынесение вычислений в Worker — последующий этап. Не добавлены S5, рисование S6, Push/Pull, boolean, новые форматы или автоматическое превращение legacy примитивов в редактируемые грани.

Защитные бюджеты: файл до 20 MB, до 100000 развёрнутых узлов, глубина вхождений до 128 и до 1 миллиона отображаемых native треугольников. Сохраняются ограничения S3 на операции. Полная перестройка затронутого отображения и snapshot история legacy команд остаются затратами; FPS больших проектов и экономия памяти не заявляются. Продвинутые действия создания/организации компонентов, native transform gizmo и диагностика больших моделей не входят в этот этап.

Следующий шаг — приёмка S4 на указанных файлах и отдельная проверка Windows в окружении Rust/MSVC/WebView2. Переход к S5 требует завершения приёмки S4.
